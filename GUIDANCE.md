# Laravel on Wodby

What Wodby sets up for a Laravel application on this service, in addition to the PHP service it is based on. Check it before committing a `.env`, hardcoding connection settings or adding a storage link step.

## Generated `.env`

When the container starts and `$APP_ROOT/.env` (`/var/www/html/.env`) does not exist, the image writes one from the container's environment variables. An existing `.env`, for example one committed to the repository, is left as it is and nothing is generated; keep `.env` out of the repository.

What the generated file contains:

| Entry | Value comes from |
| --- | --- |
| `APP_NAME` | `WODBY_APP_NAME` |
| `APP_ENV` | `WODBY_ENV_NAME`, the name of the environment |
| `APP_KEY` | `APP_KEY`, generated by Wodby |
| `APP_URL` | `WODBY_PRIMARY_URL` |
| `APP_DEBUG` | `APP_DEBUG`, on in development environments and off elsewhere |
| `DB_CONNECTION`, `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | the same variables, set by the linked database |
| `LOG_CHANNEL`, `LOG_LEVEL` | the same variables; the log channel defaults to `stderr` |
| `CACHE_DRIVER`, `SESSION_DRIVER`, `SESSION_LIFETIME`, `QUEUE_CONNECTION`, `FILESYSTEM_DRIVER`, `BROADCAST_DRIVER` | the same variables; cache and sessions default to `file`, the queue to `sync` |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `MEMCACHED_HOST` | the same variables |
| `MAIL_MAILER`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_ENCRYPTION`, `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME` | the same variables |
| `AWS_*`, `PUSHER_*`, `MIX_PUSHER_*` | the same variables |

A name that is not in this list is not written to `.env`. To change any value, set the variable on the service and deploy; do not edit the generated file. The file holds secrets: quote names, not values.

## Linked services

- **Database**: the PHP service's `DB_*` variables, including `DB_CONNECTION` and `DB_DATABASE`, which are the names Laravel's database configuration reads.
- **Storage** (required): the files volume described below.
- **Redis or Valkey** (optional): the link sets `REDIS_HOST`, `REDIS_PORT` and `REDIS_PASSWORD`, and sets `QUEUE_CONNECTION` to `redis`, so queued jobs go to the linked service. Cache and sessions stay on files unless `CACHE_DRIVER` and `SESSION_DRIVER` are set on the service.
- **Mail**: the PHP service's `MSMTP_HOST` and `MSMTP_PORT`, used by PHP's `mail()`. The `MAIL_*` entries are not filled from the mail link: they come from `MAIL_*` variables on the service, or from defaults in the image.

## Init action and files

On container start the service runs its init action (`WODBY2_SERVICE_INIT_ACTION`, here `init-laravel`):

- `storage/app/public` and `public/storage` both become links to `$FILES_DIR/public` on the files volume (mounted at `/mnt/files`, shared with the web server). This replaces `php artisan storage:link`; do not run it in the build. The step fails when one of these directories holds anything other than a `.gitignore`.
- `storage` and `bootstrap/cache` are made writable by the web user.

Only `storage/app/public` is on the volume. The rest of `storage`, such as logs and file-based sessions and cache, is in the container's file system and does not survive a restart.

## What the service runs

- After every deployment: `php artisan migrate --force`. After the first deployment only, once migrations have run: `php artisan db:seed`.
- One cron job runs `php artisan schedule:run` every minute, as Laravel's scheduler expects. Define scheduled tasks in the application; do not add cron jobs for them.
- The optional Laravel Queue service derived from this one runs `php artisan queue:listen`.

Do not add migration or queue worker commands to the build or to a start script.

## Changing configuration

Set environment variables on this service: the Laravel names in the table above and the `PHP_*` variables of the PHP service. They reach the container, and a newly generated `.env`, with the next deployment.

This service has no development workspace.

## Check the result

- `php artisan about` shows the environment, URL, and the cache, database, queue and session drivers in use.
- `php artisan migrate:status` confirms the database connection.
- `ls -l storage/app/public public/storage` shows both links to the files volume.
